Keeping our own copy of the library's data, securely, on one machine we already own.

Abstract (as submitted)

Sierra, like all ILS-shaped systems, is built to run the library right now: it updates records in place and lets the past go. Since August 2023 we've captured 51M circulation transactions covering 2.9M distinct items. About 495k of those items, roughly one in six, no longer exist in the catalog today. That's correct behavior for an operational system, but it isn't a foundation for assessing collections, patron activity, or e-resource use.

So we keep our own copy beside it. Every source is captured on a schedule, never edited after the fact, and refined into answers we can rebuild from scratch at any time. Personal details come off on the way in rather than being scrubbed out later, the raw copy is encrypted, and there's no cloud bill for the data and no vendor to leave.

I'll cover what we capture, how often, what it costs to run, and two questions the live catalog structurally can't answer. First, how long items actually spend in transit: Sierra knows an item is in transit but not the journey, so we rebuilt 403,490 of them (median 39 hours door to door). Second, where collection pressure is building, which only exists when you can compare this month's shelves to last month's.
